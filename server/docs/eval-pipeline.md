# Eval pipeline

The root `pnpm verify:l06` is a DevDigest-defined deterministic gate covering typechecks, targeted scoring and persistence tests, and the hermetic browser flow. It requires Docker and agent-browser and fails if its integration tests are skipped. It is not a course-provided verifier and does not prove the real-provider experiment or eight actual reviewed cases.

`POST /agents/:id/eval-cases/:caseId/runs` admits one scoped case using the same concurrency guard and immutable snapshot as a full suite. Its dataset fingerprint differs from a larger suite, so those runs are not compared as equivalent.

The scoped case detail endpoint returns the validated saved input; list and run endpoints do not expose it. A case name can be updated and a case can be deleted; historical suite snapshots are retained. Deletion and admission use the same agent lock.

New eval runs capture a promotion snapshot of agent fields and skill links, including hashes of skill bodies. `POST /agents/:id/eval-runs/:runId/promote` requires the caller's expected current agent version. It rejects incomplete or legacy runs and changed or missing skills, then restores agent fields and skill links and inserts an agent version atomically. Project-context attachments are not evaluated or restored. Serializable conflicts are not silently retried.

`POST /agents/:id/eval-cases` and `PUT /agents/:id/eval-cases/:caseId` save manual cases. They require one bounded unified diff with an anchor in a new-side hunk, a name and an expectation. Manual source rows have no finding ID; editing a finding-derived case converts it to a manual case. Writes are serialized with admission and reject conflicting labels for the same input. Previous run snapshots are unchanged.

On each new review, the server stores a SHA-256 fingerprint of the exact input diff, without storing its contents for evaluation. When Git commits can be resolved, it calculates the review diff using immutable base and head commit IDs and stores those IDs with the fingerprint. When the user turns an accepted or dismissed finding into a case, the server reloads the diff and verifies the entire input against that fingerprint. It stores the original file fragment intersecting the finding, its hash, and the expectation. If the original cannot be recovered or verified, including reviews created before fingerprints were recorded, case creation fails explicitly. Case creation reloads those commits even if the PR or base branch moved. If the commit objects are unavailable, creation fails. For older fingerprint-only reviews and patch-fallback reviews, the current input can be used only if it still matches the saved fingerprint. A changed PR is never silently substituted. The stored fragment can contain source code and secrets and is retained in the database with the case and its run snapshots.

`POST /findings/:id/eval-cases` creates a case from the current decision in one action. `GET /agents/:id/eval-cases`, `POST /agents/:id/eval-runs`, `GET /agents/:id/eval-runs`, `GET /eval-runs/:id`, and `GET /eval-dashboard` are workspace scoped. Runs freeze the original fragments and hashes plus agent prompt, provider, model, strategy and enabled safe skill bodies. Dynamic repo map, callers, project context, intent and memory are omitted. Existing prepared-input cases remain replayable while their registered fixtures are unchanged. Run API responses omit stored diff text; the database retains it for replay. Earlier experimental records are not automatically deleted.

Suites are limited to 100 cases and 256 KiB per diff. Cases execute sequentially. The runner requests a 120-second SDK timeout and stops scheduling more cases after failure; it retains the suite slot until the provider promise settles. A provider that ignores cancellation can therefore remain in progress past that time. Startup marks unfinished suites failed under the existing single-process assumption. Unknown costs remain null.

Scoring uses grounded findings and inclusive file/line overlap without an LLM. Recall is matched positive cases divided by all positive cases; labeled precision is matched positive cases divided by matched positives plus flagged negative cases. Findings outside the labeled anchor are counted separately as unlabeled. Citation accuracy is grounding-kept divided by kept plus dropped; it inherits the reviewer's full-file grounding exceptions. Empty denominators and incomplete suite scores are null.

`pnpm build` bundles the eval reviewer, scorer, provider adapters and SDKs into `dist/eval-engine.mjs` and writes a SHA-256 manifest. Admission loads and verifies the manifest, then executes the same immutable bytes through a data URL. The run identity hashes those bytes with the Node version, platform and architecture. Provider keys are obtained through the existing secrets provider, and providers are constructed inside the bundle; OpenRouter eval cost uses the provider-reported cost when available; without it the cost remains unknown. The build rejects unbundled dependencies other than Node built-ins. An absent, invalid or unloadable artifact, or any injected provider, falls back to the existing evaluator with engine identity `unavailable`, preventing deltas. A matching hash identifies local code and runtime, not the remote model implementation or provider behavior.

Run `pnpm build` again after changing eval, reviewer-core or provider code: evals execute the last built artifact, not subsequently edited source files. Commands and artifact paths are relative to the `server/` directory.
