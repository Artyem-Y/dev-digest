# Eval pipeline UI

On an accepted or dismissed finding, **Turn into eval case** requests a case from the server. The agent's Evals tab lists input identifiers and results, starts a suite, and links to the Eval Dashboard. The dashboard shows workspace runs and labeled metric cards; selecting an agent allows two runs to be compared. Runs with different datasets or engine/scorer versions, or incomplete runs, display raw values without metric deltas. Long prompt snapshots in the comparison scroll independently.

Precision is labeled because only accepted and dismissed anchors are classified. Unlabeled predictions and unavailable ratios are shown separately. The agent dashboard uses metric cards, a comparable-run trend and a horizontally scrollable history table with pass counts and cost; it shows a precision regression notice only when a comparable previous value exists. The history can be filtered by period, and comparison highlights changed prompt lines. A case can be run individually; the resulting run has its own dataset fingerprint. Users can create, edit and delete cases; saving edits marks a finding-derived case as manual, and prior run snapshots are retained. A newer completed run with a complete promotion snapshot can be promoted after confirmation; project context was not evaluated or restored. The server rejects a case when the original review diff cannot be recovered and verified or conflicts with another label. Comparisons suppress deltas when a verified engine artifact is absent, inputs differ, or either run is incomplete.

Run history shows case time as the sum of measured execution times for a completed run with a result for every case. This excludes queueing and orchestration. Incomplete, failed, empty, or unavailable results display an em dash.

Finding case creation is one click after accepting or dismissing a finding. The server persists the relevant original file fragment after verifying the full diff against the review fingerprint. Reviews with recorded Git commit IDs can be converted after a PR changes when those commits remain available. Older reviews without a fingerprint cannot be converted; run a new review first. The stored fragment may contain sensitive source content.

The dashboard requests all agents in one bounded batch (up to 100 agents per workspace); each admission succeeds or fails independently. Batch failures are explained in plain language, and each agent-specific failure links to that agent's Evals tab. An empty dataset or active run can prevent an individual start. Aggregate metrics and pass counts use the latest completed full-suite run, while individual-case runs remain labeled in history. Legacy runs with unknown scope remain visible but do not replace suite metrics or qualify for metric deltas or promotion.

At narrow widths the shared navigation opens from the menu button, and the history table scrolls horizontally. Both light and dark themes use the application's theme tokens.

The agent dashboard keeps the period filter alongside the run action and retains the trend and history panels when there are no runs, with empty-state text in place of invented metrics.

Metric trend points receive a small series-specific horizontal offset at each run position so identical values (especially precision and citation accuracy) remain visible instead of covering one another; their vertical position still represents the exact score.

The Agent Editor Evals tab groups metrics, frozen-input context, case actions, and run history into separate sections. Run history is a horizontally scrollable table with timestamp, status, scope, and the three metrics; an empty dataset keeps a deliberate empty state. Case rows show whether the expected finding matched the anchor and the expected-versus-actual count without requiring the row to be expanded. Provider failures remain distinct from completed runs that missed the expected finding. The editor has Diff, Files and PR meta views and displays the current expectation as JSON; the file view uses the stored anchor and PR metadata is explicitly unavailable because this case contract does not expose it. Aggregate metrics use full-suite runs only; individual and legacy runs remain labeled in history.

The Eval Dashboard follows the standalone layout: the agent header shows its provider/model badge, Configure eval cases is a compact monospace link beside the period filter and run action, and the content uses the dashboard artboard width. The all-agent recall sparkline and per-agent metric sparklines include only completed suite runs comparable with the latest run by dataset, verified engine and scorer identity. New and edit case dialogs use a two-column input/expected-output layout on desktop, a stacked layout on narrow screens, a titled header with a close action, and a primary save action in the footer.
